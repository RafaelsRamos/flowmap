# Run document format (v1)

A run document is the evidence for **one instance** of a flow: which steps it reached, what each
step looked like, and which transitions it took. It is generated by `flowmap trace` (rules in [matching.md](matching.md)) or
written by hand as a scrubbed fixture. It is never committed with real logs: logs are per
instance, contain personal data and expire. See `examples/order-fulfilment/flows/examples/`.

The schema is `packages/schema/run.schema.json` (JSON Schema draft 2020-12), exported as `runSchema`
from `@flowmap/schema`. Files are named `*.run.json` (YAML also works). `flowmap validate` skips
them; the viewer loads them and `validateRunSource` in `@flowmap/core` checks them.

```json
{
  "schemaVersion": 1,
  "flow": "order-fulfilment",
  "flowRevision": "git:3f2a9c1",
  "correlation": { "orderId": "4821" },
  "generatedAt": "2026-10-31T16:30:00Z",
  "nodes": {
    "payment": {
      "status": "success",
      "fields": { "Status": "payment.approved", "Amount": "€84.90", "Attempts": 2 },
      "evidence": [
        { "ts": "2026-10-31T09:03:00Z", "event": "payment.declined", "msg": "Card declined",
          "ref": "file://payments-api.ndjson#L31" },
        { "ts": "2026-10-31T09:05:00Z", "event": "payment.approved", "msg": "Payment approved",
          "ref": "file://payments-api.ndjson#L38" }
      ]
    }
  },
  "edges": [{ "from": "payment", "to": "payment", "label": "retry", "observed": 1 }],
  "unexpected": [{ "from": "stock-check", "to": "payment", "ts": "2026-10-31T09:02:00Z" }]
}
```

## Fields

| Field | Required | Meaning |
| --- | --- | --- |
| `schemaVersion` | yes | Always `1`. |
| `flow` | yes | Name of the flow the run was matched against. |
| `flowRevision` | no | Version of the flow file used, for example `git:3f2a9c1`. The viewer builds code links at that commit. |
| `correlation` | yes | The correlation key and value that identify the instance, e.g. `{ "orderId": "4821" }`. |
| `generatedAt` | yes | When the document was produced (ISO 8601 with a time zone). |
| `nodes` | yes | Map of node id to `status`, optional `fields` and `evidence`. A flow node left out is shown as not reached. |
| `edges` | yes | Declared transitions the instance took, with `observed` counts (self-loops such as `retry` included). `label` tells parallel edges apart. |
| `unexpected` | yes | Transitions seen in the logs that the flow does not declare: the conformance gaps. May be empty. |

`status` is `success`, `failure`, `pending` or `not_reached`. `fields` values are strings, numbers,
booleans or null: whatever the node's `evidence.display` rules extracted. `evidence` is oldest
first; each entry has `ts` and `event`, and optionally a one-line `msg` for the timeline and a
`ref` URI back to the raw log line (`file://`, `loki://`, `otel://`, depending on the adapter; see [adapters.md](adapters.md)).

## What `validateRunSource` checks

Structural (the JSON Schema): required fields, types, timestamps, statuses, kebab-case node ids,
no unknown properties (with a "did you mean" hint). Coherence rules run on a structurally valid
file; the ones marked *with flow* only run when the flow is passed in.

| Code | Severity | Rule |
| --- | --- | --- |
| `status-evidence-mismatch` | error | A `not_reached` node has evidence. |
| `evidence-out-of-order` | warning | Evidence is not oldest first. |
| `flow-mismatch` | error | *With flow:* the run names a different flow. Nothing else is compared. |
| `unknown-node` | error | *With flow:* a node key, or an `edges`/`unexpected` endpoint, is not in the flow. |
| `undeclared-edge` | error | *With flow:* an `edges` entry is not declared by the flow (it belongs under `unexpected`). |
| `declared-edge-unexpected` | error | *With flow:* an `unexpected` entry is declared by the flow (it belongs under `edges`). |
| `missing-node` | warning | *With flow:* a flow node has no entry in `nodes`. |
| `evidence-event-not-matched` | warning | *With flow:* an evidence event is not in the node's `match.event`. |

Other codes: `syntax`, `empty-file`, `missing-property`, `unknown-property`, `wrong-type`,
`invalid-value`.
